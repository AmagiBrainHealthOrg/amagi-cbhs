## Deviations and follow-ups

- SPEC §5.1 lists `territory` and `audienceType` on `form-submissions`; the ticket's scope omitted them. Added as indexed/plain text fields (values come from the `dropdowns` global, so not hard-coded selects) and updated the ticket's scope.
- `phone` (SPEC §8.1) and `industry` live in `data`, like name and email. SPEC §5.1 gives them no column, so no extra field.
- Field names: `consents.{contact, publicName, shareStory}` and `utm.{source, medium, campaign, term, content}` (columns `consents_contact`, `utm_source`, …). T012 maps the form's `consentContact` / `utm_source` names onto these.
- `airtableSyncStatus` is required with default `pending`, so the generated create type requires it: T012 passes `airtableSyncStatus: 'pending'` explicitly, as SPEC §8.2 step 3 states.
- The migration enables RLS on the new table directly (local Postgres lacks Supabase's automatic trigger) and its `down` drops the `payload_locked_documents_rels` foreign key before the table; the generated order (`DROP TABLE … CASCADE` first, then `DROP CONSTRAINT` on the already-dropped key) would error. The merged T007 migration has the same generated order in its `down` (not run here; follow-up if `down` matters).
- One `seed.int.spec.ts` › "creates nothing on a second run" failure seen once mid-session, not reproduced in four later runs; looks like a flaky interaction between parallel test files, unrelated to this ticket.
