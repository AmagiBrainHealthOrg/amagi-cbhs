## Deviations and follow-ups

- Route is `src/app/(frontend)/(site)/[slug]/page.tsx` (single segment, inside the site layout) rather than `[...slug]`, so pages get the header and footer. `home` returns 404 there. The existing hard-coded routes stay until T011 and take precedence over `[slug]`.
- The graphics moved from `(site)/_components/` to `src/components/graphics/` and are now prop-driven; the hard-coded pages use them through a thin adapter (`_components/chrome.tsx`) that T011 can delete.
- Header, footer and donate banner now read the globals and render nothing for empty fields. The local and production globals are empty until T011 seeds them, so the current pages show a bare header and footer until then. The Donate button renders only when `header.donateLabel` is set.
- `data-action` for Donate is `donate` (per AC2), replacing the old `donate_click`.
- Small UI text stays in code because the T007 block schemas have no fields for it and T009 has no migrations: roadmap status labels, countdown units, "Nov" in the week strip, "Anchor Day" map labels, landmark/aria labels ("Main", "Menu", "Footer", "The Summit in numbers"), and the not-found/error copy (there is no global for it, and the error page must not depend on the CMS). Candidates for a later schema ticket.
- The map SVG is now `aria-hidden`; the country list beside it carries the same information (the old `<title>` hard-coded Jamaica).
- Static pages (the hard-coded routes) render the globals at build time and the globals have no revalidation hook, so header/footer edits reach them only on the next deploy. `[slug]` pages are dynamic and unaffected. Worth adding global revalidation in T011.
- T017 (site lock) is not done; `[slug]` and the kitchen sink would be covered by it once it lands. Nothing implemented here.
