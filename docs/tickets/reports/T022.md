## Changes from the ticket

- No Stripe CLI and only a live key locally, so events are signed in tests with `Stripe.webhooks.generateTestHeaderString`. The ticket's `stripe listen` / `stripe events resend` checks become `tests/int/donationWebhook.int.spec.ts` plus the post-merge check below. The user chose to skip the local run against the live base.
- Idempotency is an Airtable upsert on the Checkout Session ID (new `Stripe Session` column, added by the user), not the event ID. It also covers the two events that can carry one session. SPEC §7.5 and the forms-and-tracking rule updated.
- `checkout.session.async_payment_succeeded` is handled too, so delayed payment methods are recorded once paid; `completed` with `payment_status !== 'paid'` records nothing.
- Airtable failure returns 500 so Stripe retries (up to 3 days). A missing `STRIPE_WEBHOOK_SECRET` also returns 500 and logs.
