## Deviations and follow-ups

- The `cookie-consent` global has no label for the `/cookies` link, and adding one needs a migration. The link takes its text from the cookies page's title instead (currently "Cookies"); publishing that page now also revalidates every page. If Amagi wants different link text, add a `policyLinkLabel` field in a later migration ticket.
- Only `settingsLabel` is seeded. Until Amagi fills in `heading`, `acceptLabel` and `rejectLabel` and publishes the global, no banner renders and the footer hides "Cookie settings" (a button that opens nothing would be broken). With no banner, no one can consent, so analytics stays off. This is a launch content task.
- For T015: listen for `CONSENT_EVENT` (`cbhs:consent`, `detail` is `'analytics' | 'rejected'`) and check `hasAnalyticsConsent()` from `src/lib/consent.ts` on load. `window.dataLayer` and `window.gtag` are declared there and set up by the inline head script.
- The banner is last in the DOM (sticky to the viewport bottom), so keyboard users reach it after the page content. It never covers the header, and it moves focus to itself when reopened from the footer.
- Header Donate contrast (2.36:1) fails WCAG AA: see the AC4 note.
